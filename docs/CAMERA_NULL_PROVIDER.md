# 缺少目标时的托管相机服务

托管的 Localify camera-render 服务可能存在，但未持有全部相机目标。此前 VRify 仅凭该服务存在，就假定其持有了全部三个入口并跳过了自身的 Hook，导致即使 render-begin Hook 已经安装，必需的 Unity 相机初始化仍告失败。失败清理逻辑关闭了 camera-begin 提供方，随后 Motion 的独占 render-begin 请求便可能遇到 Loader 保留的 Hook 租约。

修复方案调整为按目标逐项判断归属：

- 服务缺失或发布的目标为 null 时，采用正常的独占 Hook 获取逻辑。宿主租约失败仍按原机制处理。
- 发布的非 null 目标与预期一致时，使用共享观察者路径。
- 格式错误的服务与非 null 但不匹配的目标仍视为致命错误。
- 部分持有时，只要至少共享一个具体目标即进行订阅；直接安装的原始 Hook 则用于确立其余入口的就绪状态。
- 订阅失败绝不计入就绪状态。

本次变更未修改 Loader 的注销机制，也不允许插件抢占其他插件已有的旧租约。在检查配套修复前，请先重启初始化失败的进程。

运行时变更源自源码检查点 `b6fe8ac`。本暂存仓库保留了自身的公开 SDK、构建脚本和测试桩，未修改 Loader ABI、上游锁定、安装包配置或依赖项。

在仓库根目录下运行公开回归测试：

```powershell
python -B tests/test-shared-camera-targets.py
```

该测试使用仓库自带的 SDK，通过 MSVC 编译实际的生产选择与连接函数。覆盖范围包括服务缺失、全部 8 种目标持有子集、非 null 不匹配、未解析元数据、无效服务、订阅失败以及就绪状态判断。

已确认游戏桌面的相机回归现象在配套构建中得到恢复。该观察结论仅限于所报告的桌面相机回归，不代表单独编译的暂存 DLL、所有游戏场景、活动 XR 状态或完整相机组合矩阵均已通过验收。
